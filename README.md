# Gear VR 接 PC 串流实战记录

> 把 2015 年的三星 Gear VR 接上 PC 跑 SteamVR / VRChat 的完整过程、踩过的坑，以及**为什么最后判定为硬件极限**。

**测试设备**：Galaxy S6 Edge+（SM-G9280 / Exynos 7420 / Android 7.0）+ Gear VR SM-R323 + RTX 4060 笔记本

---

## 结论先行

| 项目 | 结果 |
|---|---|
| 系统修复 | ✅ **成功**——把已经崩溃的 Gear VR 系统救回来了 |
| 画面传输 | ✅ **成功**——9.3 MB/s、7ms 延迟，画面完整清晰 |
| 能否正常游戏 | ❌ **不能**——转头卡顿、十几分钟后发热降频 |
| 根本原因 | **硬件年限**——2015 年的 14nm 芯片跑不动实时 VR 解码 |

**如果你手上也是 S6 时代的设备，看完这行就够了：能做到“能看”，做不到“能玩”，别再浪费时间调参数。**

## 三个最有价值的发现

### 1. `Developer mode` 必须关掉，否则头显永远不挂载

Gear VR Service 的开发者选项里有两个容易被连带打开的开关：

```
Allow VR API without OSIG  → ✅ 必须开（iVRy 靠它绕过签名校验）
Developer mode            → ❌ 必须关（开了系统就不走自动挂载流程）
```

判断方法不用戴头显看画面，一条命令就够：

```bash
adb shell getprop sys.hmt.mounted    # 必须是 true
```

### 2. Oculus 组件版本错配会让整个 Gear VR 变砖，而且**能修**

Meta 在 2023–2024 年反复调整服务端，把 Gear VR 的更新机制搞坏了，导致已装好的设备变成“半截更新”状态：

```
systemdriver      9.0.0.169.450
ocms              9.0.0.130.473     ← 版本互相不配套
vrshell           9.0.0.170.450
systemutilities   9.0.0.232.450
```

症状是插入头显毫无反应，日志刷 `NoClassDefFoundError: com.oculus.os.SettingsObserverCallback`。

**解法**：从 `vault.gearvr.net` 取一套配套版本（Galaxy S8 提取），逐个 `adb install -r -d` 覆盖。详见 01 篇「阶段 4」。

### 3. H.264 会黑屏，必须用 H.265

数据在传（9.3 MB/s）但头显全黑。原因是：

- **H.264 编码在部分设备组合上输出黑屏**（社区多个相同报告）
- **`Subsampling` 必须 4:2:0**，老硬解芯片不认 4:2:2
- **JPEG 是软解**，靠 CPU 一帧帧解，Exynos 7420 撑不住 → 一卡一卡

## 为什么到极限（数据）

| 指标 | 实测 | 正常值 |
|---|---|---|
| 传输速率 | 9.3 MB/s | ✅ |
| 网络延迟 | 7 ms | ✅ |
| 渲染帧率 | 58 Hz | 目标 60 |
| **显示帧率** | **40 Hz** | ❌ 丢 18 帧 |

端到端链路：

```
陀螺仪采样 → Wi-Fi → 电脑渲染 → 编码 → 回传 → 手机解码 → 显示
└──────────── 合计 60–100ms（真头显 <20ms）────────────┘
```

**加上 60Hz 屏 + 3DoF + 无散热空间，这台设备的 VR 天花板就在这里。**

## 更好的选择

| 目标 | 推荐 |
|---|---|
| 想躺着玩 PC 游戏 | **Moonlight 串平面画面**（不吃性能，不烫） |
| 想看电影 / galgame | Gear VR + 串流当**私人巨幕**（静态内容本来就不吃帧率） |
| 真想在 VR 里玩 | **二手 Quest 2**（6DoF + 90Hz + 独立运行） |
| 别买 | 二手 S10+——仍是 60Hz + 3DoF + 串流，换个寂寞 |
